## 개요

오늘은 다음 버전 26.10.2를 다듬었습니다. 다른 사람이 만든 사건이 편집 화면으로 열리던 문제를 고치고, 기본 사건을 끝낸 사람에게 공공 사건기록보관소를 소개하는 안내를 넣었습니다. 올리기와 받기가 실패할 때의 안내도 한국어로 바꿨습니다. 개발 쪽에서는 코드 저장소를 팀 조직으로 옮기면서 배포 흐름이 끊기지 않게 했고, 망가진 DNS 레코드를 두 번 되돌렸습니다.

## 받은 사건을 편집기로 열지 않게 하기

공공 사건기록보관소에서 받은 사건을 플레이하려던 사람이 "열기"를 눌러 편집 화면에서 헤매는 모습을 봤습니다. 사건을 만든 사람이 아닌데도 편집기로 들어가는 길이 두 곳 있었습니다.

| 들어가던 곳 | 바꾼 동작 |
|---|---|
| 보관소 사건 정보의 "열기" 버튼 | 만든 사람에게만 보여요. 다른 사람에게는 "플레이"와 새 판의 "업데이트"만 보여요 |
| 나의 사건에서 받은 사건 표지 누르기 | 편집기 대신 플레이를 시작해요. 길게 누르기 메뉴도 "플레이"를 보여 줘요 |

만든 사람인지 판단하는 곳을 한곳으로 모아서, 나중에 화면이 늘어나도 같은 기준이 쓰이게 했습니다. 받은 사건의 주된 동작은 플레이라서, 눌리는 모양의 표지가 플레이를 시작하는 편이 자연스럽다고 판단했습니다.

## 기본 사건을 끝내면 보관소로 이끌기

기본 사건을 해결한 사람은 다음에 무엇을 할지 모를 수 있습니다. 그래서 기본 사건을 해결하고 홈으로 돌아오면, 둘러보기에 처음 들어갈 때 보이는 환영 안내를 한 번 보여 주기로 했습니다.

| 항목 | 정한 것 |
|---|---|
| 언제 | 기본 사건을 해결하고 사건 화면을 닫았을 때 |
| 몇 번 | 처음 한 번만 |
| 누구에게 | 보관소에서 사건을 받아 본 적이 없는 사람 |
| 버튼 | "둘러보기 시작"을 누르면 바로 둘러보기로 이동 |

> **참고:** 로그인하지 않은 사람도 버튼을 누르면 그대로 둘러보기로 갑니다. 둘러보기 화면이 로그인을 안내하기 때문에 따로 막지 않았습니다.

## 실패 안내를 한국어로 바꾸기

사건을 올리다 용량 제한에 걸리면, 실패 이유가 서버가 보낸 영어 문장 그대로 보였습니다.

| 경우 | 이제 보이는 안내 |
|---|---|
| 사건 파일이 너무 큼 | 사건 파일이 너무 커요. 15MB 이하로 줄여 주세요(지금 OO MB). |
| 네트워크 | 인터넷에 연결되지 않았어요. 연결을 확인한 뒤 다시 시도해 주세요. |
| 더는 받을 수 없는 사건 | 이 사건은 더 이상 받을 수 없어요. |
| 새 버전 앱으로 만든 사건 | 새 버전의 앱으로 만든 사건이에요. App Store에서 앱을 업데이트한 뒤 다시 받아 주세요. |

사건 파일 크기 제한은 15MB로 올렸고, 올리기 전에 크기를 먼저 재서 미리 알려 줍니다. 목록에 쓰는 표지는 어떤 고화질 배경이든 정해진 크기 아래로 줄여 만들도록 했습니다.

## 코드 저장소를 팀 조직으로 옮기기

앱과 서버의 코드 저장소를 개인 계정에서 팀 조직으로 옮겼습니다. 가장 신경 쓴 곳은 Slack 명령으로 시작하는 배포 흐름이었습니다.

| 단계 | 한 일 |
|---|---|
| 저장소 옮기기 | 이름은 그대로 두고 소유자만 팀 조직으로 바꿈 |
| 빌드 연결 | Xcode Cloud에서 저장소 주소만 새로 연결해 기존 워크플로를 그대로 씀 |
| 확인 | Slack 명령으로 빌드해 TestFlight까지 올라가는지, 빌드 번호가 이어지는지 확인 |

옮긴 뒤 첫 빌드도 이전과 같은 시간 안에 TestFlight에 올라왔고, 빌드 번호도 끊기지 않고 이어졌습니다.

## DNS 레코드가 망가졌을 때 바로 되돌리기

새벽에 문서 사이트를 새 주소로 옮긴 뒤, 같은 도메인에 다른 레코드를 손보는 과정에서 문서 사이트 주소 레코드가 두 번 망가졌습니다.

| 언제 | 일어난 일 | 되돌린 방법 |
|---|---|---|
| 레코드 값을 바꿀 때 | 값을 고치는 중에 레코드가 저장되지 않고 사라짐 | 같은 레코드를 다시 추가 |
| 다른 레코드를 추가할 때 | 문서 사이트 주소 레코드의 값이 다른 레코드의 이름으로 바뀜 | 값을 원래대로 다시 입력 |

두 번 모두 DNS 서버에 직접 물어봐서 바로 알아챘습니다. 공용 DNS에 남아 있던 이전 값 덕분에 사이트가 실제로 끊기기 전에 되돌릴 수 있었습니다.

> **중요:** 도메인 관리 화면에서 레코드를 하나 고치면 같은 화면의 다른 레코드도 함께 바뀔 수 있습니다. 이제는 레코드를 저장할 때마다 다른 중요한 레코드가 그대로인지 DNS 서버에서 다시 확인합니다. App Store 심사 중인 앱이 처리방침 주소로 이 사이트를 가리키고 있어서, 주소가 끊기면 심사에도 영향을 줄 수 있었습니다.
