## 개요

오늘은 여섯 개 저장소에 코딩 에이전트가 읽는 규칙 파일을 새로 정리했습니다. 매번 읽어야 하는 규칙은 `AGENTS.md`에, 특정 폴더에서만 필요한 규칙은 경로별 규칙에, 여러 단계로 된 절차는 스킬에 나눠 담았습니다. 앱에서는 다음 버전 26.10.2에서 Mac 사건 편집기도 사진 보관함에서 사진을 고르고, 사진 앱에서 사진을 바로 끌어다 놓을 수 있게 했습니다.

## 에이전트 규칙을 세 가지로 나누기

지금까지 저장소의 규칙은 README와 `CLAUDE.md`, 그리고 한 컴퓨터의 Claude 메모리에 나뉘어 있었습니다. 새 팀원이 다른 도구로 작업하면 이 규칙을 읽을 수 없었고, 같은 내용이 여러 곳에 있다 보니 한쪽만 고쳐지는 일도 있었습니다.

Claude Code는 작업 폴더의 `AGENTS.md`를 읽습니다. 하지만 같은 폴더에 `CLAUDE.md`가 있으면 `AGENTS.md`는 읽지 않습니다. 그래서 규칙의 원본은 `AGENTS.md` 하나로 두고, `CLAUDE.md`에는 그 파일을 가져오는 한 줄만 남겼습니다.

```markdown
@AGENTS.md
```

그다음 규칙을 언제 필요한지에 따라 세 곳으로 나눴습니다.

| 파일 | 언제 읽히나 | 담은 것 |
|---|---|---|
| `AGENTS.md` | 작업을 시작할 때마다 | 저장소가 하는 일, 빌드와 테스트 명령, 결정 권한, 함께 작업할 때 지킬 것 |
| `.claude/rules/*.md` | 정해진 경로의 파일을 다룰 때만 | 법적 문서, 마이그레이션, visionOS 화면처럼 일부 폴더에만 해당하는 규칙 |
| `.claude/skills/*/SKILL.md` | 해당 작업을 할 때만 | 출시 태그 붙이기, 마이그레이션 적용, 처리방침 바꾸기 같은 여러 단계 절차 |

`AGENTS.md`는 모두 100줄 아래로 맞췄습니다. 자주 바뀌는 테스트 개수 같은 숫자는 넣지 않았습니다.

> **참고:** 경로별 규칙은 파일 맨 위에 적용할 경로를 적어 둡니다. 예를 들어 법적 문서 규칙은 처리방침과 약관 페이지를 고칠 때만 읽힙니다. 덕분에 매번 읽는 규칙은 짧게 유지하면서, 실수하기 쉬운 곳의 규칙은 놓치지 않습니다.

## 공용 규칙과 개인 규칙 나누기

초안을 검토하면서 문제가 하나 보였습니다. 운영자의 Claude 세션끼리 결정을 주고받는 방식처럼, 이 컴퓨터에서만 필요한 규칙이 공용 파일에 섞여 있었습니다. 이대로 두면 팀원의 도구도 맞지 않는 규칙을 따르게 됩니다.

그래서 이런 규칙은 git에 올라가지 않는 개인 파일 `CLAUDE.local.md`로 옮기고, `AGENTS.md`에는 "운영자의 결정을 받는다"처럼 누구에게나 맞는 말만 남겼습니다.

| 파일 | 저장소에 올라가나 | 누가 읽나 |
|---|---|---|
| `AGENTS.md` | 올라감 | 모든 코딩 에이전트 |
| `CLAUDE.md` | 올라감 | Claude Code |
| `CLAUDE.local.md` | 올라가지 않음 | 이 컴퓨터의 Claude Code |

개인 파일을 두는 저장소의 `.gitignore`에는 `CLAUDE.local.md`를 넣었고, 이번에 정리한 모든 저장소에는 `.claude/*.lock`도 넣었습니다. lock 파일은 Claude Code가 작업 중에 만드는 파일인데, 지금 컴퓨터에서는 이미 무시되고 있었습니다. 다른 컴퓨터에서 저장소를 받아도 잘못 커밋되지 않도록 저장소 설정에도 넣었습니다.

팀원이 맡은 저장소에는 직접 넣지 않고, 이슈로 같은 구성을 제안했습니다.

## Mac 편집기에서 사진 보관함 쓰기

어제 iPhone과 iPad의 사건 편집기에는 사진 보관함에서 사진을 고르는 기능을 넣었습니다. Mac은 여전히 파일 선택 창만 쓸 수 있어서, 사진 앱에 있는 사진을 넣으려면 먼저 파일로 내보내야 했습니다.

Mac도 iPhone, iPad와 같은 메뉴를 쓰게 했습니다.

| 버튼 | 메뉴 항목 |
|---|---|
| 이미지 선택 · 이미지 바꾸기 | 사진 보관함에서 선택 |
| | 파일에서 선택 |

시스템 사진 선택기는 앱 밖에서 동작합니다. 그래서 사진 보관함 접근 권한을 따로 묻지 않고, 사용자가 고른 사진만 앱에 전달됩니다. iOS에서만 쓰던 코드를 모든 플랫폼에서 같이 쓰게 되면서, 플랫폼마다 다른 코드도 하나 줄었습니다.

메뉴 항목과 버튼 이름에서 말줄임표(…)를 뺐습니다. 이 버튼은 이제 창이 아니라 메뉴를 열기 때문입니다.

끌어다 놓기도 넓혔습니다. 지금까지는 Finder의 이미지 파일만 받았는데, 사진 앱은 파일이 아니라 이미지 데이터를 넘깁니다. 두 형식을 모두 받게 해서 사진 앱의 사진도 이미지 칸에 바로 끌어다 놓을 수 있게 했습니다. iPad에서 사진 앱의 사진을 편집기로 끌어 오는 것도 같이 됩니다.

> **참고:** 어떤 방법으로 고른 사진이든 같은 크기로 줄여서 사건 파일에 넣습니다. 사건 파일이 불필요하게 커지지 않게 하기 위해서입니다.
