## 개요

오늘은 셜록 홈즈 단편 「신랑의 정체」를 옮긴 사건 파일을 공공 사건기록보관소에 올릴 수준으로 다듬기 시작했습니다. 한 세션이 모든 일을 하지 않고, 총괄 세션이 스토리 · 추리 · 비평 · 검수 세션에 일을 나눠 맡겼습니다. 앱은 다음 버전 26.10.3을 TestFlight에 올렸고, App Store 심사 도구는 Keystone이라는 이름으로 출시를 준비했습니다. 스튜디오 웹사이트는 첫 화면의 워드마크와 인트로를 고쳤습니다.

## 원작 사건을 여러 세션이 나눠 다듬기

처음 만든 사건 파일에는 종류가 잘못 들어간 증거가 많았습니다. 사람의 기억이 현장 증거로 들어가 있었고, 진술로 들어가야 할 내용이 문서로 들어가 있었습니다. 원작에 없는 표와 날짜도 섞여 있었습니다.

운영자는 기준을 하나로 정했습니다. **원작에 충실하게 만들고, 각색이 필요하면 원작 문장에 근거해야 합니다.** 이 기준으로 일을 다섯 세션에 나눴습니다.

| 세션 | 맡은 일 |
|---|---|
| 총괄 | 사건 의뢰서를 쓰고, 세션 사이의 수정 요청을 정리하고, 사건 파일을 만들어 앱 규칙으로 검사 |
| 스토리 | 의뢰 내용과 진술을 원작 문장과 하나씩 대조해 다시 배치 |
| 추리 | 증거 종류를 바로잡고, 잠긴 증거와 선택지 · 힌트를 설계 |
| 비평 | 추리 설계를 점검 항목과 원작 충실 기준으로 비평 |
| 검수 | 사건 내용을 모르는 풀이자에게 사건을 풀게 해 난이도를 확인 |

각 세션은 산출물마다 원작의 어느 문장에 근거했는지 표로 남깁니다. 비평 세션이 인용한 영문 근거는 총괄 세션이 원작 본문에서 실제로 있는지 다시 확인했습니다.

## 첫인상으로 난이도 재기

목표 난이도는 '중'입니다. '중' 사건은 처음 열린 단서만 읽었을 때 범인이 가장 의심받는 사람이면 안 됩니다. 총괄 세션은 인물과 지명을 바꾼 사본을 다른 모델에 보여 주고, 관계자마다 범인일 확률을 매기게 했습니다.

| 측정 | 범인 의심도 평균 | 순위 |
|---|---|---|
| 1차 (첫판) | 49% | 1위 |
| 2차 (의뢰 내용에서 가게 매각 · 출장 이야기를 옮김) | 52% | 1위 |
| 3차 (돈 이야기를 그 돈을 다루는 인물의 진술로 옮김) | 45% | 1위 |
| 4차 (원작 속 의뢰인의 말 두 문장을 더함) | 44% | 1위 |

수정할 때마다 원작의 사실은 바꾸지 않고, 각 사실을 **어디서 보여 줄지만** 옮겼습니다. 의심도는 내려왔지만, 범인은 계속 1위였습니다. 측정한 모델이 매번 원작을 알아봤기 때문입니다.

운영자는 이 상태로 스토리를 잠그기로 했습니다. 첫인상 기준을 맞추지 못한 것은 원작 인지와 원작 충실 때문인 예외로 기록하고, 추리 단계로 넘어갔습니다.

> **참고:** AI는 사람보다 추리를 잘하고, 유명한 원작은 기억으로 풀기도 합니다. 그래서 이 숫자는 원작을 모르는 사람이 느낄 난이도보다 쉽게 나온 값입니다. 최종 난이도는 사람이 직접 플레이해서 확인할 예정입니다.

추리 세션은 글로 된 편지는 문서로, 마차와 초대장 같은 물건은 현장 증거로 나눴습니다. 비평 세션의 지적을 반영한 수정본은 앱 규칙과 형식 검사를 모두 통과했고, 지금은 검수 단계에 있습니다.

## 26.10.3 준비하기

다음 버전 26.10.3에 세 가지를 넣고 TestFlight에 올렸습니다.

| 바꾼 것 | 내용 |
|---|---|
| 받은 사건 카드 | 홈과 나의 사건에서 작성자 대신 의뢰인 이름을 보여 줌 |
| 계정 보안 | 자체 보안 테스트 결과를 바탕으로, 다른 사용자에게 보이는 계정 정보를 화면에 필요한 만큼으로 줄여 보안을 강화함 |
| 화면 문구 | 닉네임 변경 안내, 업데이트 안내, 삭제 확인, 보관소 환영 안내를 해요체로 맞춤 |

화면 문구는 운영자가 TestFlight 빌드에서 직접 확인했습니다. 지금 심사 중인 26.10.2는 이 변경과 관계없이 10월 20일에 자동 출시됩니다.

## 스튜디오 웹사이트 첫 화면 다듬기

스튜디오 웹사이트의 이름을 글꼴 대신 붓글씨 이미지로 바꾸고, 폭을 위쪽 로고 그림과 같게 맞췄습니다.

같은 날 "첫 화면의 로고 인트로가 사라졌다"는 보고가 있었습니다. 원인을 찾아보니 코드 문제가 아니라 Mac의 저전력 모드였습니다. 저전력 모드에서는 Safari가 영상 자동 재생을 막고, 사이트는 재생이 막히면 인트로를 건너뛰었습니다.

| 상황 | 전 | 후 |
|---|---|---|
| 영상 재생이 막힘 | 마지막 장면이 바로 보임 | 첫 장면 그림이 가운데에 크게 보였다가 로고 자리로 옮겨 감 |
| 동작 줄이기 설정 | 인트로 없음 | 그대로 인트로 없음 |

운영자가 저전력 모드를 켠 Mac Safari에서 새 동작을 확인했습니다.

## App Store 심사 도구를 Keystone으로 출시 준비하기

10월 16일에 들인 App Store 심사 도구는 지금까지 사내에서만 썼습니다. 오늘은 이 도구에 Keystone이라는 이름을 붙이고, App Store에 올릴 수 있게 준비했습니다.

| 준비한 것 | 내용 |
|---|---|
| 이름 · 아이콘 | 앱 이름을 Keystone으로 정하고, 새 앱 아이콘과 홈 화면의 Keystone 워드마크를 넣음 |
| 첫 실행 안내 | 처음 열면 시작 안내를 보여 주고, API 키를 넣었는데 앱이 보이지 않으면 키 화면에서 안내를 다시 열 수 있게 함 |
| 개인정보 | 추적하지 않고 수집하는 데이터가 없다는 개인정보 매니페스트를 넣음 |
| 첫 업로드 | App Store에 처음 올릴 버전과 빌드 번호를 정함 |

Keystone은 Casebook과 마찬가지로 서버 없이 기기에서 App Store Connect와 바로 통신하고, API 키는 기기 밖으로 나가지 않습니다.
